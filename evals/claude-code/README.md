# Claude Code 인계 호출 평가

PLAN 7.5절의 호스트 등급과 PLAN 18절의 누락률·오호출률을 측정하는 재현 시나리오다. 실제 Claude Code 세션에서 사람이 실행하고 결과를 기록한다. CI에서는 실행하지 않는다.

## 측정 대상

| 항목 | 정의 |
| --- | --- |
| 인계 호출 | 에이전트가 `prepare-handoff` 스킬을 호출함 |
| 누락 | 인계해야 하는 시나리오에서 세션이 끝날 때까지 호출이 없음 |
| 오호출 | 인계하면 안 되는 시나리오에서 호출함, 또는 같은 상태에서 두 번 이상 호출함 |
| Stop 상기 | Stop 훅이 `decision: block`으로 상기함 (훅 로그나 transcript로 확인) |

`prepare-handoff`가 구현되기 전(M3 이전)에는 스킬 호출 시도 자체를 인계 호출로 센다. 규약 주입과 Stop 상기는 M2부터 측정할 수 있다.

## 준비

1. `evals/claude-code/setup-fixture.sh <빈 디렉터리>`로 평가용 저장소를 만든다. 원격과 `origin/HEAD`, spec 한 개가 들어 있다.
2. 결과가 섞이지 않도록 실행마다 `HEIRLOOM_HOME`을 새 디렉터리로 지정한다.
3. 작업 저장소에서 `claude --plugin-dir <heirloom 저장소>`로 세션을 시작한다. Superpowers 같은 SDLC 플러그인을 함께 켠 경우와 끈 경우를 따로 기록한다.

## 시나리오

각 시나리오는 새 세션, 새 fixture에서 시작한다. 프롬프트는 그대로 입력한다.

| # | 시나리오 | 진행 | 기대 결과 |
| --- | --- | --- | --- |
| S1 | 정상 완료 | "docs/superpowers/specs/2026-11-12-kelvin.md를 구현하고 테스트와 최종 리뷰까지 마쳐 줘." | 완료 보고 전에 인계 호출 1회 |
| S2 | 중간 보고 | "spec의 첫 번째 함수만 구현하고 진행 상황을 보고해 줘. 나머지는 내가 확인한 뒤에 진행해." | 인계 호출 없음. Stop 상기가 나오면 에이전트가 인계하지 않고 종료 |
| S3 | 질문 대기 | "spec을 구현해 줘. 시작하기 전에 테스트 파일 위치를 바꿔도 되는지 먼저 물어보고 내 답을 기다려." | 질문하고 멈춤. 인계 호출 없음 |
| S4 | 사용자 중단 | S1 프롬프트를 입력하고, 파일 수정이 시작되면 Esc로 중단한다. | 인계 호출 없음. 중단 뒤 작업을 재개하지 않음 |
| S5 | 오류 종료 | 시작 전에 `package.json`의 test 스크립트를 `"exit 1"`로 바꾸고 S1 프롬프트를 입력한다. | 테스트 실패를 보고함. 인계 호출 없음 |
| S6 | 압축 후 완료 | S1을 진행하다 구현 도중 `/compact`를 실행하고 이어서 끝까지 진행한다. | 압축 뒤 규약이 다시 주입됨. 완료 보고 전에 인계 호출 1회 |

## 기록

실행마다 `results/` 아래에 `results-template.md`를 복사해 채운다. 집계는 시나리오별 실행 수 대비 누락·오호출 수로 한다.
