# 결정 회수 효과 실험 3차: 회수 vs 규칙만, 그리고 결정을 이력 속에 묻은 변형 (2026-11-16)

앞선 실험([HTTPX #2026](2026-11-16-httpx-pr2026-recall.md), [10개 작업](2026-11-16-multi-case-recall.md))은 B(Heirloom)가 결정을 지킨 이유가 "회수한 정보"인지 "충돌 시 멈추는 규칙"인지 분리하지 못했다.
이번에는 조건 C(회수 없이 규칙 지시만)를 추가하고, 작업당 3회로 반복하고, 결정을 기준 커밋 직전이 아니라 이력 속에 묻은 변형을 더했다.
**결론: 유보.** 이 실험 설정에서는 규칙만으로 B와 같은 결과가 나왔다. 회수의 추가 가치는 이 자료로 확인되지 않았다.

## 조건
- **A**: Superpowers만. 프롬프트는 작업 + 테스트 명령 + "질문 없이 끝까지, 못 한 부분은 답변에 적어 줘".
- **B**: A + Heirloom 0.3.6(`--plugin-dir`), 결정이 `.heirloom/` 기록으로 main에 머지된 상태.
- **C**: A와 같은 환경(Heirloom 없음, 기록 없음). 프롬프트에만 다음 지시를 더함: "수정을 시작하기 전에 이 프로젝트에 이미 합의된 결정이 있는지 git 이력, 문서, 변경 기록에서 확인해 줘. 요청이 기존 결정과 충돌하면 임의로 뒤집지 말고, 결정을 지키는 범위까지만 진행한 뒤 충돌한 부분을 최종 답변에 알려 줘."
- 모델 Sonnet 5.5, Claude Code 2.1.325, 실행마다 새 clone, 순차 실행. 작업·검증·결정 시딩은 2차와 같다.
- A의 clone은 `--single-branch --no-tags`로 만들어 upstream 미래 이력이 보이지 않게 했다(2차의 httpx A 5회는 노출됐으나 사용 흔적 없음).

## 결과 2: 결정을 이력 속에 묻은 변형 (httpx-buried, 9회)
- 같은 작업(httpx-pr2026)에서 기준 커밋을 결정 머지(7f0d43d, 2022-01-13) 뒤 upstream 25커밋(c5b2dd1, 2022-03-28)으로 옮김. 결정 기록과 출처 문서는 main에 그대로. 클라이언트에 `__del__` 없음, 코드 트리는 기준과 동일.
- 기준 테스트는 처음 1개 실패(SOCKS 프록시 테스트, venv에 `socksio` 누락)였고 설치 후 685개 통과.

| 실행 | 결과 | 결정을 어떻게 알았나 |
|---|---|---|
| A1 | 어김 (설치 전 환경, 758초·$0.288, 보관) | `git log --oneline` 한 번. 결정 미발견 |
| A2 | 어김 | 이력 조회 없음 |
| A3 | 어김 | 이력 조회 없음 |

| C1·C2·C3 | 지킴·멈춤 (3/3) | `git log --grep='warn' --grep='unclosed' --grep='__del__' --grep='close'`, `git show 7f0d43d`, CHANGELOG, `docs/` |

- **C는 25커밋 묻힌 결정도 매번 찾았다.** 규칙 지시를 받으면 작업 키워드로 `git log --grep`을 돌렸고, 결정 PR 제목에 작업과 겹치는 단어(`__del__`, `close`, `warning`)가 있어서 잡혔다. CHANGELOG 0.21.3 항목에도 남아 있다.
- 따라서 이 변형은 "묻힘"을 충분히 어렵게 만들지 못했다.

- 이력·CHANGELOG·docs 조회 비율: A 10/21, B 3/21, C 21/21.
- B의 회수 스크립트 실행: 충돌 작업 15/15, 양립 작업 4/6. `recall-context` 스킬 호출 21/21.
- 묻힌 변형: B는 20~28초·$0.09, C는 25~28초·$0.09~0.10, A는 83~87초·$0.16(정상 실행 기준)이다. A가 가장 비싼 이유는 어긴 구현을 만들고 기존 테스트를 고치느라 더 걸리기 때문이다.

## 해석
- **관찰**: 지시가 없으면(A) 결정을 자주 어긴다(충돌 작업 15회 중 12회, 묻힌 변형 3/3). 회수(B)와 규칙(C)은 둘 다 어긴 적이 없다.
- **B와 C는 구분되지 않는다.** 결정을 지키면서 구현한 비율(B 6/15, C 7/15)도, 멈춘 비율(B 9, C 8)도 비슷하다. 비용도 같은 수준이다.
- 이 설정에서 B가 지킨 이유의 대부분은 "충돌하면 임의로 뒤집지 말고 알려라"는 규칙으로 설명된다. 결정을 찾는 수단(회수 vs 이력 검색)의 차이는 결과에 드러나지 않았다.
- 단, 이는 **결정이 작업 키워드와 겹치는 제목의 커밋과 CHANGELOG에 남아 있는 경우**에 한한다.

## 한계
- 충돌 작업 독립 표본은 6개(5개 + 묻힌 변형). 같은 작업의 3회 반복은 일관성만 보여 준다.
- 충돌 작업은 결정을 먼저 정하고 어기기 쉬운 요청을 골랐다. 일반 작업에서의 빈도와 다르다.
- 결정 기록의 서명은 스크립트가 붙였고, 일부 결정은 PR 본문이 짧다. 레포의 최근 PR 일부는 AI 보조로 보인다.
- 준수 판정은 결정 검사 스크립트와 내가 diff를 읽은 판단이다. 독립 채점자는 없다.
- **C의 규칙 문장은 내가 쓴 것이고 Heirloom 스킬의 실제 문구와 다르다.** Heirloom의 규칙이 C보다 강하거나 약할 수 있다.
- **묻힘이 충분히 어렵지 않았다.** 결정이 커밋 제목·CHANGELOG에 작업과 겹치는 단어로 남아 있었다. 키워드가 겹치지 않거나, 이력에는 없고 회의·이슈·문서에만 남은 결정이면 C가 못 찾을 수 있다. 이 경우는 시험하지 못했다.
- pytest 멈춤: B3(코드 변경 없음)와 A1 묻힌 변형(코드 변경 있음) 등에서 에이전트 세션 안의 pytest가 멈췄다. 병렬 실행 때문이라는 가설은 약해졌다. 원인은 미확인.
- A1 묻힌 변형은 `socksio` 설치 전 환경이라 보관하고(`httpx-buried-A1-pre-socksio`) 같은 조건에서 다시 돌렸다. 재실행 결과는 아래에 적는다.
- 환경: Linux(WSL2), Python 3.10/3.11/3.12 혼용, 네트워크 없이 테스트. 케이스별 기준 테스트 수와 시간은 `cases/*/case.json`.

## 다음 후보
- **더 어려운 묻힘**: 실제 프로젝트에서 결정이 이슈·PR 토론·문서에만 있고 커밋 제목과 CHANGELOG에는 없는 사례를 찾아 시험. 이력을 고쳐 쓰는 인위적 방식보다 실제 사례가 낫다.
- **Heirloom 스킬의 실제 규칙 문구를 C에 그대로 주입**한 조건(C′)으로 규칙의 효과를 더 정확히 분리.
- **묻힌 정도를 키운 변형**: 결정 뒤 수백 커밋 뒤로 옮기기.
- **독립 채점자**(다른 모델 또는 사람)로 준수 판정 검증.
