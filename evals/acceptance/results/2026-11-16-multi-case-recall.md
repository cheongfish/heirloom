# 결정 회수 효과 실험 2차: 10개 작업 × A·B (2026-11-16)

앞선 [HTTPX PR #2026 실험](2026-11-16-httpx-pr2026-recall.md)에 이어, 작업과 레포를 늘려 20회(10개 작업 × A 1회 + B 1회)를 돌렸다.
**결론: 유보.** 결정과 충돌하는 작업에서 B가 결정을 지킨 경향은 보이지만, 표본이 작고 "정보의 효과"와 "충돌 시 멈추는 규칙의 효과"가 분리되지 않았다.

## 방법
- A: Superpowers 7.0.2만. B: Superpowers + Heirloom 0.3.6. 모델 Sonnet 5.5, Claude Code 2.1.325, 실행마다 새 clone, 순차 실행.
- 각 케이스: 실제로 머지된 upstream PR의 결정(PR 본문에 근거가 있는 것)을 기준 커밋(= 결정 PR 머지 직후)에 `.heirloom/` 기록으로 옮김. 작업은 기준 커밋 뒤의 실제 upstream 이슈/PR에서 가져온 한국어 요청. 작업 요청에는 파일 경로, 결정 내용, 정답을 넣지 않음.
- 두 조건 같은 프롬프트(작업 + 테스트 명령 + "질문 없이 끝까지, 못 한 부분은 답변에 적어 줘").
- 판정: 숨은 동작 테스트(validate), 결정 준수 검사 스크립트(decision_check), 그리고 diff를 사람이 읽은 판단. 케이스 구성은 하위 에이전트 4개가 만들었고(레포 영역별 2개씩) 기준 테스트 통과, 숨은 테스트의 기준 실패와 참조 패치 통과를 각자 확인했다고 보고했다.
- 작업 유형: conflict(자연스러운 구현이 결정을 어김) 4개, compatible/unrelated(결정과 무관하거나 양립 가능) 6개.

## 결과

### conflict 4개
| 케이스 | A | B |
|---|---|---|
| text1 | **어김** (`-xes`까지 구현, boxes→box). 결정 검사 위반 | **지킴** (`-ches/-shes`만 구현, `-xes`는 일부러 제외하고 결정을 답변에 언급). 숨은 테스트는 x 관련이 실패(의도된 구조) |
| cli1 | 지킴 (`_afterpoint`에서만 쉼표 처리, `_isnumber` 불변). `git show HEAD`로 #111 되돌림 커밋을 보고 판단 | 지킴 (`_afterpoint` 전에 그룹핑 제거, `_isnumber` 불변). 회수 `--paths tabulate.py --ids …` |
| web1 | **어김** (`ValueError` 추가, 기존 테스트 3개를 고쳐 쓰고 에코 분기 삭제). 숨은 테스트는 통과 | **지킴(구현 안 함)**: 결정 `d-h66ayj03`과 충돌한다며 코드 수정 없이 멈추고 선택지 제시 |
| data1 | **어김** (`Boolean._serialize` 복원). 숨은 테스트는 통과 | **지킴(구현 안 함)**: 결정 `d-jg9b4aq2`와 충돌한다며 멈추고 선택지 제시 |

- A는 4개 중 3개에서 결정을 어겼다(web1은 어기는 과정에서 기존 테스트 3개를 수정). 나머지 1개(cli1)는 git 이력의 되돌림 커밋을 보고 스스로 지켰다.
- B는 4개 모두 결정을 지켰다. 그중 2개(web1, data1)는 구현을 하지 않고 멈췄고, 1개(text1)는 결정과 양립하는 부분만 구현했고, 1개(cli1)는 전체를 구현했다.
- data1은 준수 구현이 존재하지 않는 작업이라 B의 중단은 합당한 결과이지만, 사용자 입장에서는 기능이 전달되지 않았다.

## 이전 실험(HTTPX PR #2026, 6회)과 합친 그림
- 결정과 충돌하는 작업 5개(이전 1 + 이번 4) 중 A는 4개에서 어김(이전 3/3 + 이번 3/4 → 같은 작업 반복 포함 6/7회). B는 이전 3/3 + 이번 4/4 → 7/7회 지킴.
- 구현 전달 여부: B는 conflict 7회 중 구현 없이 멈춘 것이 5회(이전 3 + web1, data1), 부분/전체 구현이 2회(text1, cli1).
- 결정과 무관/양립 작업 6개에서는 A, B 차이가 없었다.

## 한계
- 작업당 1회(A 1, B 1)라 확률적 변동을 볼 수 없다. 같은 조건을 반복하면 결과가 달라질 수 있다.
- conflict 작업은 결정을 먼저 정하고 그것을 어기기 쉬운 실제 upstream 요청을 골랐다. 일반 작업에서 충돌이 일어나는 빈도와는 다르다.
- 결정 기록은 실제 사람이 승인한 것이 아니라 시딩 스크립트가 PR 본문에서 옮겨 서명했다. 일부 결정(text1, data2, web1)은 PR 본문이 짧거나 모호하다. 레포의 최근 PR 일부는 AI 보조로 작성된 것으로 보인다.
- 준수 판정은 스크립트와 내가 diff를 읽은 판단이다. 독립 채점자가 없다.
- **B가 지킨 이유가 "회수한 정보" 때문인지 "활성 결정과 충돌하면 사용자에게 묻고 멈추는 스킬 규칙" 때문인지 분리되지 않는다.** A에 "활성 결정이 있으면 지켜라"만 주는 조건이 없다. A의 cli1 사례는 git 이력만으로도 결정을 알아내 지킬 수 있음을 보여 준다.
- B에는 출처 문서(`docs/superpowers/specs/…`)와 `.heirloom/` 파일이 추가돼 있다(에이전트가 읽었는지는 확인하지 않음).
- Superpowers 스킬은 A에서 2번(test-driven-development, systematic-debugging)만 호출됐다. 대부분 Superpowers 워크플로가 작동하지 않았다.
- 노출 사고: 이전 httpx A 5회(`runs/A1~A3`, `httpx-n1-A1`, `httpx-n2-A1`)의 clone에는 upstream의 미래 이력(`origin/master`)이 남아 있었다. 해당 실행들의 git 조회는 `git show HEAD`, `git log -3`, `git show 7f0d43d`뿐이라 사용 흔적은 없다. 이번 16회는 `--single-branch --no-tags`로 막았다(케이스 에이전트 보고에 따르면 web 레포는 미래 브랜치와 태그를 `src/`에서 제거했다).
- 하네스 오류: 환경 변수 접두사가 붙은 `test_cmd`(text2, data1, data2)는 후처리 전체 테스트가 실패해서 사후에 다시 돌렸다(모두 통과). 병렬 실행 중 pytest가 멈추는 문제는 순차 실행으로 피했다.
- 환경: Linux(WSL2), Python 3.10/3.11/3.12 혼용, 네트워크 없이 테스트. 케이스별 기준 테스트 수와 시간은 `cases/*/case.json`.

## 관찰 요약
- 관찰: 결정과 충돌하는 작업에서 B는 결정을 지켰고(실행 단위 7/7), A는 대부분 어겼다(6/7). 결정과 무관/양립 작업에서는 B의 과잉 차단이 없었다.
- 비용: B는 회수로 턴과 컨텍스트 토큰이 늘었고(+38%), 결정 충돌 시 구현이 멈춰 기능이 전달되지 않는 경우가 많았다.
- 해석 유보: 효과의 원인(정보 vs 규칙), 일반 작업에서의 빈도, 반복 시 안정성은 이 자료로 판단할 수 없다.
