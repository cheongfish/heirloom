## A1. 정상 완료

| 확인 | 결과 |
| --- | --- |
| 완료 보고 **전에** `prepare-handoff`를 1회 호출함 | |
| 대시보드가 작업마다 한 번 자동으로 열림 | |
| 작업 경계(브랜치, 변경 파일, spec)가 맞음 | |
| decision 초안이 spec의 결정을 출처 인용과 함께 담음. 연관 코드 경로에 마크다운이 없음 | |
| 인계 직후 `wait-approval.mjs`를 백그라운드로 실행함 | |
| 세션이 살아 있으면 승인 직후 묻지 않고 반영함 (세션이 끝난 뒤 승인했다면: 요청 전에는 반영하지 않음) | |
| 기록 파일이 `.heirloom/decisions/`에 쓰이고 커밋됨. 커밋 메시지가 fixture의 `.gitmessage`를 따름 | |
| PR 본문의 요약이 사람이 고친 최종 요약과 글자 그대로 같음 (로컬 모드: PR을 만들지 않고 `unsupported_remote`를 알림) | |
| 머지 전 새 세션 색인에서 새 decision이 `[머지 대기]`로 보임 | |
| 머지 뒤 새 세션 색인에서 `[머지 대기]`가 사라지고 마지막 fetch 시각이 머지 뒤임 | |
| (로컬 모드) 머지 전에는 'PR은 만들 수 없음, 직접 머지'로 안내되고, 머지 뒤에는 미처리 인계에서 빠짐 | |
| `recall-context`가 그 decision을 `status: active`로 돌려줌 | |
