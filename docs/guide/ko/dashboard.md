# 대시보드

[English](../en/dashboard.md)

대시보드는 사람이 인계를 검토하고 승인하는 로컬 웹 화면입니다. 사용자마다 서버 하나가 `127.0.0.1`에서 뜹니다.

## 열기

- **자동.** 인계를 제출하면 작업마다 처음 한 번 브라우저가 자동으로 열립니다. 사용자 설정 `dashboard.openBrowser`로 끌 수 있습니다.
- **직접.** 에이전트에게 "Heirloom 대시보드 열어줘"라고 요청하면 됩니다. 특정 작업을 열려면 작업 ID를 함께 말합니다.
- **주소.** 기본값은 `http://127.0.0.1:17380/`입니다. 포트는 [설정](configuration.md)에서 바꿀 수 있습니다.
- **브라우저가 안 열릴 때.** WSL에서는 `wslview`를 쓰고, 없으면 `cmd.exe /c start`를 씁니다. 그래도 열지 못하면 에이전트가 주소를 알려 주니 직접 붙여 넣으세요.

## 전체 목록

| 영역 | 내용 |
| --- | --- |
| 승인 대기 | 사람의 승인을 기다리는 인계 |
| 맥락 정리 | 저장소별 미검토 decision 수, 마지막 정리, **정리 실행** 단추. [제안 조건](curation.md#정리를-제안하는-시점)을 만족한 저장소에는 "정리 권장"이 붙습니다. 정리가 진행 중이면 대신 "정리 진행 중"이 보입니다. |
| 인계되지 않은 변경 | 코드 변경이 있지만 현재 상태로 인계를 준비하지 않은 작업 트리 |
| 오래된 미처리 건 | 끝나지 않은 작업 중 마지막 활동이 `dashboard.staleDays`(기본 7일) 넘게 지난 것. 시간이 지나도 자동으로 만료되지 않습니다. |
| 진행 중, 최근 끝난 작업 | 나머지 작업 |

전체 목록을 볼 때 PR을 만든 작업은 `gh`로 PR 상태를 백그라운드에서 확인하므로, 목록이 네트워크를 기다리지 않습니다. 머지되지 않고 닫힌 PR의 작업은 '만료됨'이 되고 열린 화면에 반영됩니다. 머지된 PR은 다시 확인하지 않고, 나머지는 5분이 지나면 다시 확인합니다. `gh`가 없으면 아무것도 바뀌지 않습니다.

## 작업 화면

작업 화면은 탭으로 나뉩니다. 승인 바는 모든 탭의 하단에 고정되어 있습니다.

| 탭 | 내용 |
| --- | --- |
| 개요 | 작업 경계(저장소, 브랜치, 검토 대상 소스 상태, 변경 파일, 자료), 누락·충돌·경고. 확인할 알림이 있으면 탭에 배지가 붙습니다. 증분 재확인이면 기준 승인, 그 뒤에 바뀐 파일과 자료, 연결 없는 변경도 보입니다. |
| PR 요약 | 요약 불릿 편집, 추가, 삭제, 초안으로 되돌리기 |
| decision | 항목별 승인·거절·보류. 추가 항목은 제목과 본문을 고칠 수 있습니다. "decision 모두 승인" 버튼이 있습니다. |
| axiom | 항목별 승인·거절·보류. 일괄 승인에 포함되지 않습니다. |
| 승인 내용 | 승인 뒤에 보입니다. 최종 요약, 항목별 결정, 서명 키 지문 |

- **편집과 갱신.** 편집하는 중에 에이전트가 초안을 다시 제출하면, 입력은 그대로 두고 "새 초안이 있음" 배너만 띄웁니다.
- **승인 버튼.** 모든 항목을 결정해야 켜집니다.
- **승인 이후 재확인.** 승인 뒤에 코드가 바뀌었으면([작업 흐름](workflow.md#승인-이후-변경)) 승인을 유지하는 항목은 "승인 유지"로 표시되어 접혀 있고, 그런 요약 불릿은 고칠 수 없습니다. 재확인 대상은 이유와 "지난 승인 내용"을 함께 보여 줍니다. "다시 검토"를 누르면 유지 항목도 다시 결정할 수 있습니다. 열린 항목만 결정하면 되고, 열린 항목이 없으면 요약을 확인하는 한 번의 동작으로 끝납니다.
- **폐기.** "작업 폐기"는 그 인계를 끝냅니다. 폐기한 작업은 승인하거나 반영할 수 없습니다.
- **정리 작업.** [맥락 정리](curation.md)도 같은 탭을 씁니다. 개요에는 전용 worktree, 헤드리스 실행 상태(실패하면 "다시 실행"), 정리 묶음과 이전 검토 이력이 보입니다. axiom 후보에는 근거 decision과 이유 입력란이 있고, 보류·거절하려면 이유가 필요합니다. 승인을 저장하면 헤드리스 반영 단계가 시작됩니다.

## 서버 수명

- 열린 화면이 없고 30분 동안 요청이 없으면 서버가 스스로 종료됩니다. 시간은 `dashboard.idleMinutes`로 바꿀 수 있습니다.
- 모든 상태는 디스크에 있으므로 서버가 꺼져도 잃는 것은 없습니다. 다음 인계나 대시보드 열기 요청 때 다시 뜹니다.
- 플러그인을 업데이트하면 다음 실행 때 서버가 새 코드로 다시 시작됩니다.

## 포트 충돌

다른 프로그램이 포트를 쓰고 있으면 대시보드를 시작하지 않습니다. 인계와 승인 대기 상태는 그대로 보존됩니다.

```sh
lsof -i :17380
ss -ltnp 'sport = :17380'
```

포트를 쓰는 프로그램을 끄거나, `dashboard.port`를 다른 값으로 바꾸세요.
