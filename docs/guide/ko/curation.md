# 맥락 정리

[English](../en/curation.md)

인계마다 그 작업의 decision이 기록됩니다. 시간이 지나면 decision이 반복되거나 겹치고, 같은 규칙을 지키고 있었다는 것이 드러나기도 합니다. 맥락 정리는 아직 함께 검토한 적 없는 decision 묶음을 살펴보고 다음을 제안합니다.

- 중복 정리(대체 또는 폐기)
- 기존 기록 사이의 관계: 예외 또는 병존. 조건을 반드시 적습니다.
- 기존 axiom의 수정
- 새 axiom 후보: decision 두 개 이상이 근거인 규칙

맥락 정리는 선택 기능이며 사용자가 고를 때만 실행됩니다. 대시보드에서 제안을 항목마다 승인하기 전에는 아무것도 바뀌지 않고, 승인한 제안도 PR이 머지되어야 활성이 됩니다.

## 정리를 제안하는 시점

decision이 대상 브랜치에서 활성이고, 머지된 어떤 정리에서도 검토되지 않았으면 **미검토**입니다. 다음 중 하나를 만족하면 정리를 제안합니다.

- 미검토 decision이 10개 이상
- 미검토 decision이 3개 이상이고, 마지막 정리(정리한 적이 없으면 가장 오래된 미검토 decision의 승인) 뒤 30일이 지남

제안은 대시보드 전체 목록의 '맥락 정리' 카드와 세션 시작 때의 한 줄 안내로만 보입니다. 대화상자로 작업을 끊지 않습니다. 기준값은 [프로젝트 설정](configuration.md#프로젝트-설정)(`curation.*`)으로 바꿀 수 있습니다. 개수는 마지막으로 가져온(fetch) 대상 브랜치에서 읽으며, 이를 계산하려고 fetch하지는 않습니다.

## 정리 실행

1. 대시보드 전체 목록의 저장소 카드에서 **정리 실행**을 누르고 확인합니다.
2. 대시보드 서버가 대상 브랜치를 가져온 뒤, `~/.heirloom/worktrees/<repoId>/<taskId>/`에 전용 worktree를 만들고 대상 브랜치에서 새 브랜치 `heirloom/curate-<날짜>-<접미사>`를 만듭니다. 사용자의 작업 트리는 건드리지 않습니다.
3. 그 안에서 헤드리스 에이전트(기본값 `claude -p`)를 `curate-decisions` 스킬로 실행합니다. 에이전트는 미검토 decision을 오래된 순으로 최대 20개, 그와 관련된 활성 기록, 모든 활성 axiom, 이전 검토 이력을 읽고 초안을 제출합니다.
4. 인계와 같은 작업 화면에서 제안을 검토합니다. axiom 후보에는 근거 decision이 함께 보입니다. **후보를 보류하거나 거절하려면 이유를 적어야 하며**, 이유는 저장소에 남습니다.
5. 승인을 저장하면 대시보드가 헤드리스 에이전트를 `apply-approval` 스킬로 다시 실행합니다. 에이전트는 기록과 검토 이력을 쓰고 커밋한 뒤 브랜치를 push하고 PR을 엽니다.
6. PR이 머지되면 그 묶음은 검토된 것이 되고, 전용 worktree와 로컬 브랜치가 지워집니다. 작업을 폐기하거나 PR이 머지 없이 닫혀도 지워집니다. 커밋되지 않은 변경이 있는 worktree는 지우지 않고, 작업 화면에 이유를 보여 줍니다.

저장소마다 한 번에 하나의 정리만 실행됩니다.

## 검토 이력

승인된 정리는 기록 옆에 `.heirloom/curation/c-<id>.json`을 쓰고 같은 PR로 커밋합니다. 검토한 묶음, 후보마다 사람의 결정(수락·보류·거절)과 이유, 그 밖의 제안이 들어 있습니다.

보류하거나 거절한 후보는 새 근거 없이 다시 제안되지 않습니다. 후보가 인용한 decision이 모두 이전에 보류·거절된 후보의 근거에 들어 있으면 출처 검사가 초안을 거부합니다.

## 헤드리스 실행이 실패하면

실행이 실패하거나, 시간 상한(30분)을 넘기거나, 시작하지 못하면(실행 파일 없음) 작업은 그 상태에 그대로 있습니다. 작업 화면이 이유와 로그 파일을 보여 주고, 두 가지 방법을 안내합니다.

- **다시 실행:** 같은 단계를 다시 실행합니다. 자동으로 재시도하지는 않습니다.
- **직접 실행:** 화면에 보이는 worktree로 `cd`한 뒤 Claude Code를 열고 `/curate-decisions`(승인 전) 또는 `/apply-approval`(승인 뒤)을 실행합니다.

## 한계

- 헤드리스 에이전트는 사용자 권한으로 실행되고 사용자의 `gh`·`glab` 로그인을 씁니다. 단계마다 쓸 수 있는 도구를 제한합니다([보안](security.md#헤드리스-정리-실행) 참고).
- PR은 github.com 원격에서, MR은 GitLab 원격에서만 만듭니다. 다른 원격이면 기록을 정리 worktree에 커밋하는 데까지 하고, 브랜치 push와 머지는 직접 해야 합니다.
- 실행 명령은 사용자 설정 `curation.agent`에서 읽습니다([설정](configuration.md#사용자-설정)). 지금은 Claude Code 프로필만 있습니다.
